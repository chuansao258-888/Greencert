# Responsive Web Interface

GreenCert is a responsive website, not a native Android or iOS application. The shared header provides the wallet button and Sepolia label. A bottom navigation bar links Home, Market, Applications, My RECs, Activity and Account. Cards appear in one column on narrow screens and two columns where there is room. Buttons and navigation links have touch-sized targets.

## Pages

| Route | Main content |
|---|---|
| `/` or `/dashboard` | Workflow explanation, issued/listed/sold/retired counts, source quantity chart and certificate status chart. |
| `/market` | Active listings with source, complete batch quantity and total test ETH price. |
| `/certificates/{id}` | Public site, quantity, owner, status, price, retirement statement and on-chain events. |
| `/applications` | Producer application form and list, or Admin review queue and evidence access. |
| `/my-certificates` | Owned batches with listing, repricing, cancellation or retirement controls. |
| `/activity` | Wallet transactions saved after receipt verification. |
| `/account` | Role registration, wallet balance, sale proceeds and withdrawal. |

## User flow

The Producer connects MetaMask, signs the session challenge and registers the Producer role. The application form asks for site code and name, source, two-letter country code, a completed generation period, batch index, quantity from 1 to 100 and a PDF, PNG or JPEG evidence file up to 5 MiB. One quantity unit represents one simulated REC and 1 MWh. The browser uploads evidence, requests canonical metadata, checks its hash and submits the application transaction. The Admin opens the application list, downloads evidence and approves or rejects with a reason.

An approved batch appears in My Certificates. The Producer lists all of its units at one total price and may change or cancel that listing. Market cards display the complete quantity and price. A Buyer confirmation repeats both values before the exact-price purchase transaction. The Producer's proceeds remain claimable until Withdraw is clicked. The Buyer can retire the complete purchased batch after entering a beneficiary and purpose. The public certificate page continues to show the owner, fixed quantity and retired status.

Wallet actions display a prompt message, wait for a receipt, send the hash to the server for verification and then refresh the page. Empty states explain when there are no applications, listings, certificates or transactions. If deployment configuration is missing, contract-derived data is unavailable until the addresses, blocks and RPC URL are supplied.

## Dashboard charts

The source chart uses horizontal bars for Solar, Wind, Hydro and Unknown. Values are labeled in MWh; one REC equals 1 MWh in this simulation. Zero-value sources are omitted. The status chart shows the number of Active and Retired certificate batches. Both charts use visible text labels as well as bar lengths, so the value is still readable without colour. With no issued certificates they show an empty message. Before contract deployment they show a configuration message instead of sample figures. At wider viewports the two charts sit side by side; on narrow viewports they stack vertically.
