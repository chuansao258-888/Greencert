# Mobile Interface

## Layout and Navigation

Design the application for a narrow mobile viewport first. Use a single column of cards on phones, two columns where appropriate on tablets, and a sidebar with wider content panels on desktop. Primary controls have a minimum 44-pixel touch target. Avoid horizontal scrolling in forms and certificate cards.

The mobile bottom navigation contains Home, Market, Mine and Account. For the Admin, Review replaces Mine. Role-specific actions remain visible within the relevant record rather than appearing as separate navigation items.

Display `Sepolia Testnet` and `Simulated REC` where they affect a purchase or environmental claim. Format short wallet addresses for readability and provide a copy control for the complete address. Use CSS or SVG charts backed by API data.

## Pages

| Route | Page | Main content and actions |
|---|---|---|
| `/` or `/dashboard` | Home | Issued, listed, sold and retired totals; source chart; role-specific next action. |
| `/market` | Market | Available certificate batches, quantities, source filters, fixed total prices and links to details. |
| `/certificates/{id}` | Certificate | Site, generation period, quantity, total MWh, owner, status, metadata integrity and history; permitted listing, purchase or retirement actions. |
| `/applications` | Applications / Review | Producer's applications or Admin review queue; status filters. |
| `/applications/new` | New Application | Generation details, evidence upload, metadata review and submission. |
| `/applications/{id}` | Application | Submitted details, evidence link, on-chain status and review outcome. |
| `/my-certificates` | My Certificates | Holdings; Producer listing controls or Buyer retirement controls. |
| `/activity` | Activity | Personal verified transactions, status and explorer links; retry verification where needed. |
| `/account` | Account | Wallet, network, role registration, sign-in state and seller proceeds withdrawal. |

## Producer Workflow

The application form collects site code, site name, energy source, country, generation period, batch index, quantity and evidence file. Explain that one quantity unit is one simulated REC corresponding to 1 MWh, that the quantity must be from 1 to 100, and that the complete batch will be traded and retired together. Show accepted file types and the size limit before selection.

After upload, present a summary of the normalised fields. Generate immutable metadata and verify its hash before enabling the wallet submission. Once submitted, show the transaction hash and pending confirmation state. A confirmed application appears in the Producer's application list.

For issued certificates, provide a positive total-price input and a listing confirmation showing the batch quantity and total MWh. A listed certificate exposes Change price and Cancel listing. After a sale, show claimable proceeds in Account with a separate Withdraw action.

## Admin Workflow

The review queue opens a detailed application with evidence download, generation fields and metadata integrity. Approval is enabled only after the required evidence loads and the on-chain fields match the metadata. Rejection requires a reason; the application stores its immutable content before submitting the rejection transaction.

Display the final status after confirmation. An application that another action has already approved, rejected or withdrawn must refresh and disable unavailable controls.

## Buyer Workflow

Certificate details show source, generation period, quantity, total MWh, current owner, total listing price and history. Before purchase, reload the listing and verify metadata. The confirmation states that the complete batch will be purchased, displays the exact total test ETH price and explains that the wallet also estimates a network fee.

After purchase, the certificate batch appears in My Certificates. Retirement asks for a beneficiary and purpose and presents the full quantity with a confirmation that the entire batch will be retired and cannot be traded or retired again. A retired record continues to show its owner, quantity, declaration and transaction history.

## Interaction States

| State | Interface behaviour |
|---|---|
| Wallet disconnected | Show Connect wallet and keep public browsing available. |
| Wrong network | Show the expected network and offer a wallet network switch. |
| Role unregistered | Offer Producer or Buyer registration; explain that the selection is permanent. |
| Session expired | Request a new sign-in signature before an authenticated API action. |
| Loading | Show placeholders or a progress indicator without invented values. |
| Empty | Explain the absence of records and offer a relevant next action. |
| Awaiting wallet | Ask the user to review the wallet request; prevent repeated clicks. |
| Submitted | Display the transaction hash and wait for a receipt. |
| Confirmed | Refresh authoritative data and show the completed action. |
| Wallet rejected | Return to the form without claiming the action was submitted. |
| Reverted | Show a readable reason where available; refresh potentially stale state. |
| Confirmation unavailable | Keep the hash and offer Check transaction. |
| Metadata missing or mismatched | Explain the verification issue and disable approval or purchase confirmation. |
| RPC unavailable | Show a retry action; label previously loaded information as stale. |

When MetaMask emits an account or chain change, cancel stale requests, end the authenticated session, clear role-dependent state and reload the signer and contract instances. Do not retain an action prepared for the previous account.

## Interface Acceptance

- Check layouts at widths of 360, 390, 768 and 1280 pixels.
- Test the full workflows in MetaMask's mobile browser, including wallet prompts, return navigation and account changes.
- Associate labels with inputs, support keyboard focus and show field-level validation messages.
- Keep long addresses, hashes and filenames from breaking the layout.
- Show amounts consistently in test ETH; perform conversions from integer wei.
- Use status text as well as colour, and maintain readable contrast.
- Make confirmed ownership and retirement visible after refresh.

Responsive screenshots support the layout review but do not replace a real mobile wallet test.
